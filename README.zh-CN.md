这是我的 **Monash 学期交换项目追踪系统** 的作品集安全公开演示版。

私有正式系统会抓取项目搜索数据、标准化字段、进行字段级变化检测、保留历史快照、比较不同申请轮次、生成对比报告，并发布受访问控制保护的查看页面。本公开仓库只展示用户端的筛选、排序和变化对比流程，不公开真实生产数据、客户可见的实际对比结果，也不公开生产抓取器内部实现。

> **合成数据说明：** 本仓库中的院校、国家/地区、URL、日期、成绩、竞争状态、上一轮数值和名额均为虚构内容。数据仅用于驱动界面与变化检测演示，不来源于生产环境。

## 这个 Demo 展示什么

- 英文 / 简体中文界面切换
- 按大学或国家/地区搜索
- 地区、学期、时长、可申请校区、学院、申请状态和竞争状态等多维筛选
- 同一筛选维度内使用 OR，不同维度之间使用 AND
- **动态联动筛选数量**：其他条件变化时，各选项数量同步更新
- 根据当前筛选结果实时变化的 Total / Green / Yellow / Red / Closed 统计卡
- 表头交互式排序
- 最低要求、上一轮分数线与预计名额展示
- **运行时读取合成上一轮基准并自动比较**，生成竞争、名额、分数线、开放/关闭和新增项目等变化标签
- 搜索页与详情页字段不一致的警告展示
- **可排序的 QS 排名列**（虚构排名）：综合名次、区间名次、回落到上一年榜单，专业型院校显示最好的学科名次（悬停或点按查看全部学科），"未收录"与排名差明确区分
- **可折叠的变化汇总面板**：十个格子统计与上一轮相比的分数线、名额、竞争、开放状态变化和新增项目，跟随左侧筛选，点一下即可筛选表格
- **逐日变化记录**：显示在格子旁边，点校名会在表格里搜索这所学校
- **登录页预览**：照正式版设计复刻（中英文、手机、深色模式），不校验任何账号
- 使用生产 schema 的精简演示字段结构
- 桌面端和小屏幕响应式布局

公开页面会明确标注为 **静态作品集 Demo**，而不是实时 Monash 数据服务。

## 对比功能如何工作

`data/current.json` 是完全合成的当前轮数据，`data/comparison.json` 是独立的合成上一轮基准。浏览器会真正比较两份 JSON，再动态生成变化标签；变化结果不是直接写死在 HTML 里的。

变化语义与正式查看器一致。例如：名额减少、同口径分数线上升视为不利变化；名额增加、同口径分数线下降、竞争缓和或重新开放视为有利变化。

## 技术栈

| 部分 | 用到的技术 |
| --- | --- |
| 爬虫与数据流水线 | Python 3、`requests`、BeautifulSoup 配合 `lxml`，网站拒绝普通 HTTP 请求时才改用 Playwright（无头 Chromium） |
| 报告与排名 | 用 `openpyxl` 生成 Excel 对比报告，并构建 QS 排名表 |
| 测试 | pytest，配合裁剪过的 HTML 样本和替身抓取器 |
| 定时运行 | 家里一台 Debian 机器上的 systemd 定时器，跑完把新数据推送到 GitHub |
| 查看页面 | 纯 HTML、CSS 和 JavaScript，不用框架，通过 GitHub Actions 部署到 GitHub Pages |
| 登录 | 只用 Python 标准库写的小服务，签发 HMAC 签名的 Cookie，由 Nginx `auth_request` 校验 |

## 私有正式系统的工程要点

私有正式系统从 2026 年 8 月起每天运行。在不公开代码和数据的前提下，这里列出它背后的工程决策：

- **克制且会自检的采集。** 从搜索页自动发现全部约 164 个学期交换项目，不写死学校名单；单线程逐个请求，每次运行都实时读取 `robots.txt` 并遵守 30 秒的抓取间隔。详情页失败时沿用旧值而不是删掉；搜索页失败则整轮中止、数据原封不动；发现的项目数比上一轮少了 20% 以上时触发安全阀，不写入任何文件。
- **原文与标准化值并存。** 每个字段都同时保存页面原文和标准化后的值，任何变化都能追溯到网站当时的原话。
- **始终正确的对比。** 上一轮申请季被冻结为基准，对比结果每次都作为（基准, 当前数据）的纯函数重新生成，而不是在原表上增量修改，所以错误的行不会越积越多。
- **不会悄悄配错的 QS 排名。** 可排序的 QS 列覆盖 164 所合作院校中的 150 所：以 2027 和 2026 综合榜为主，专业型院校改用学科榜并显示其最好的学科名次。匹配使用人工核对过的别名表，因为最初的自动匹配把香港大学配成了香港都会大学（#781 而不是 #11）；只要还有一所没解决，构建就会失败。
- **真正有人在用的查看页面。** 可折叠的变化汇总面板按上一轮统计分数线、名额、竞争和开放状态的变化，点一下就能筛出对应学校，并列出逐日变化记录。访问需经过独立的中英双语登录页：签名会话 cookie、按 IP 限制登录频率，改密码或删账号后已有登录立即失效。
- **在真实运行中修掉的可靠性问题。** 无人值守运行暴露出几个值得一提的 bug：生成的数据文件里混进了 git 冲突标记（改为先同步再抓取，并在有冲突时拒绝提交）；读-改-写竞态覆盖了回填的日期；`set -o pipefail` 下 `grep -q` 匹配成功反而因 SIGPIPE 被判为失败；以及 macOS 的 launchd 任务因为桌面文件夹的隐私保护从未真正执行过。
- **放在网站接受的机器上定时跑。** Monash 网站对 GitHub 托管的 runner 一律返回 HTTP 403，所以抓取放在家里一台 24 小时开机的 Debian 小主机上：每天 19:00 跑一次，另外每两小时检查一次，只有上一次定时抓取超过 20 小时才补抓。手动抓取不会占掉当晚那一次。
- **离线测试。** 解析器测试使用精简后的 HTML 样本；流水线测试通过替身抓取器跑完整流程：首次运行、无变化重跑、真实变化、项目移除、安全阀触发、搜索页失败和详情页失败。

### 登录设计

查看页面最初放在 Web 服务器的 Basic Auth 后面，用的是浏览器自带的账号密码弹窗。换掉这个弹窗属于体验改进，所以设计目标是：只改变"怎么登录"，不改变"谁能进来"。成品可以看[登录页预览](./signin.html)。

- **复用现有的密码校验，而不是自己重写。** 原来的账号文件仍然是唯一的账号来源，校验也仍然交给本来就支持 apr1 和 bcrypt 哈希的 Web 服务器：一个很小的登录服务去问 Web 服务器上一个只对本机开放的接口，这组用户名和密码能否通过同一套 Basic Auth 校验。整个过程没有写任何密码哈希代码。
- **每个请求都在入口处检查。** Web 服务器在返回任何内容之前，先问登录服务这个会话 cookie 是否有效；没有有效会话的人一律转到登录页。
- **无状态但仍可撤销的会话。** cookie 里放的是用户名、过期时间，以及对这两者加上"该用户在账号文件中那一行的指纹"计算出的 HMAC。系统不需要会话存储，但只要改了密码或删了用户，指纹就会变化，这个人已有的登录立即失效，不用重启任何东西。更换签名密钥则会让所有人退出登录。
- **合理的默认值。** 勾选"保持登录"可以保持 30 天；不勾选的话，关闭浏览器就失效，而且最长不超过 12 小时。每个 IP 每分钟最多尝试登录 6 次，超出后页面会提示稍等，而不是默默失败。
- **运维上没有新负担。** 添加、修改、删除账号的命令和以前完全一样。登录服务在沙箱里运行，不需要自己的系统账户；登录页模板每次请求都会重新读取，所以文案修改会随常规代码更新自动上线。
- **对用户很重要的小细节。** 登录过期时会回到登录页，而不是报一句 JSON 解析错误；在登录页选的语言会带到表格页；页面支持中英文、手机和深色模式，查看页面右上角有退出登录按钮。

## 隐私边界

公开仓库明确不包含：

- 真实 Monash 交换项目记录；
- 真实历史快照和字段级变化日志；
- 真实上一轮冻结基准；
- 自动生成的对比 Excel / JSON 报告；
- 客户实际查看的对比结果；
- 生产账号、密码、访问控制配置和基础设施细节；
- 生产 scraper / crawler 源代码。

这样可以公开展示工程设计和交互能力，同时把实时数据、历史资产与客户服务留在私有生产环境中。

## 本地运行

页面通过 `fetch()` 加载 JSON，因此应启动一个简单的本地 HTTP server：

```bash
python3 -m http.server 8000
```

然后访问：

```text
http://localhost:8000/
```
